# Forma Praxis Marketing Website - Agent Guide

This is a **Laravel 13 marketing website** with a public contact form and admin dashboard. See [README.md](README.md) for general Laravel framework information and [Laravel Boost docs](https://laravel.com/docs/ai) for AI-optimized tools.

## Quick Start

### Setup
```bash
composer run-script setup   # One-time: install, env, key, migrations, build
npm run dev                 # Concurrent: serve, queue, logs, vite HMR
composer test              # Run PHPUnit suite
```

### Test User
- Email: `admin@example.com`
- Password: `password`
- Auto-created by `database/seeders/DatabaseSeeder.php`

## Project Structure

| Directory | Contains |
|-----------|----------|
| `app/Http/Controllers/` | Route handlers (ContactController, AdminContactController, HomeController) |
| `app/Models/` | Eloquent models (User, ContactMessage) |
| `app/Mail/` | Mailable classes (ContactMessageMail) |
| `database/migrations/` | Schema definitions (users, contact_messages, jobs, cache) |
| `database/seeders/` | Initial data (admin user) |
| `database/factories/` | Model factories for testing |
| `resources/views/` | Blade templates (welcome.blade.php for form, admin inbox) |
| `resources/js/` | Vue 3 components (if adding frontend interactivity) |
| `routes/` | Route definitions (web.php for HTTP, console.php for Artisan) |
| `tests/Feature/` | Integration tests (ContactFlowTest validates form → email → auth) |
| `config/` | Application settings (database, mail, auth, session) |

## Core Features

### 1. Public Contact Form (No Auth)
- **Route**: `GET /` (display), `POST /contact` (submit)
- **Controller**: `ContactController@index`, `ContactController@store`
- **Model**: `ContactMessage` (name, email, message, timestamps)
- **Validation**: name, email, message required
- **Action**: Saves submission → sends email via `ContactMessageMail`

### 2. Email Notification
- **Mailable**: `app/Mail/ContactMessageMail.php`
- **Recipient**: Configured in `config/mail.php` (`MAIL_FROM_ADDRESS`)
- **Testing**: Queued synchronously (queue driver = sync)

### 3. Admin Dashboard (Auth Required)
- **Route**: `GET /admin/contacts`
- **Middleware**: `auth` (session-based via Laravel UI)
- **Controller**: `AdminContactController@index`
- **View**: Admin inbox listing all contact submissions

### 4. Authentication
- **Guard**: `web` (session-based)
- **Routes**: Generated by `Auth::routes()` (login, register, password reset)
- **UI**: Laravel UI scaffolding (Blade templates + Bootstrap)

## Database

### Models
- **User**: name, email, password, timestamps (Authenticatable)
- **ContactMessage**: name, email, message, timestamps (no foreign keys)
- **Job**: Infrastructure for queued tasks (sync queue, never persists)
- **Cache**: Infrastructure for cache storage (uses file system)

```bash
php artisan migrate           # Apply pending migrations

```

## Testing

### Run Tests
```bash
composer test                    # Full suite
php artisan test tests/Feature/ContactFlowTest.php  # Single test
php artisan test --profile=pest  # With Laravel Pint
```

### Test Database
- Uses `RefreshDatabase` trait (in-memory SQLite, isolates each test)
- Test config in `phpunit.xml` (database=`:memory:`, in-process)
- **Key test**: `ContactFlowTest.php` validates form submission → email → admin auth

### Testing Patterns
```php
use Tests\TestCase;
use Illuminate\Foundation\Testing\RefreshDatabase;

class ContactFlowTest extends TestCase {
    use RefreshDatabase;
    
    public function test_contact_form_stores_message() {
        // Arrange: User logs in, submits form
        $response = $this->post('/contact', [
            'name' => 'John', 'email' => 'john@example.com', 'message' => 'Hello'
        ]);
        
        // Assert: Message saved, email queued, user redirected
        $this->assertDatabaseHas('contact_messages', ['email' => 'john@example.com']);
    }
}
```

## Build & Assets

### Frontend Stack
- **CSS**: Tailwind CSS 4 + Bootstrap 5 scaffolding + custom SASS in `resources/sass/`
- **JS**: Vue 3 + Axios + Laravel Vite plugin for HMR
- **Builder**: Vite 8 (fast, dev server with hot reload)

### Build Commands
```bash

npm run build  # Production: minify, hash assets
```

### Asset Pipeline
- Source: `resources/css/app.css`, `resources/js/app.js`
- Output: `public/build/manifest.json` (production) or dev server (dev)
- Blade: Use `@vite()` to load assets with cache busting

## Configuration

### Key Files
- `.env`: Environment variables (MAIL_FROM_ADDRESS, DATABASE_URL, APP_KEY)
- `config/app.php`: App name, timezone, language
- `config/database.php`: DB driver (SQLite dev, MySQL production)
- `config/mail.php`: SMTP/Mailer (Mailtrap/Laravel test account)
- `config/auth.php`: Guard (web = session), provider (users table)
- `config/session.php`: Driver (file dev, cookie production)

### Database Driver
- **Dev**: SQLite at `database/database.sqlite`
- **Production**: Set `DB_CONNECTION=mysql` in `.env`

## Common Workflows

### Add a New Feature
1. Create migration: `php artisan make:migration create_table_name --create`
2. Define model: `php artisan make:model ModelName -m`
3. Add controller: `php artisan make:controller FeatureController`
4. Update routes: Add to `routes/web.php`
5. Create views: Add Blade templates in `resources/views/`
6. Test: Create feature test in `tests/Feature/`

### Modify Database Schema
```bash
php artisan make:migration add_column_to_table --table=table_name
# Edit migration, then:
php artisan migrate
```

### Debug Issues
```bash
php artisan tinker                # Interactive REPL
php artisan pail                  # Stream logs in real-time
php artisan config:clear          # Clear config cache
php artisan cache:clear           # Clear all caches
```

## Special Notes for AI Agents

- **Laravel Boost** is installed → Use `php artisan boost:install` to enable 15+ AI-friendly skills
- **PSR-4 autoloading** via Composer: `App\` → `app/`, `Database\` → `database/`, `Tests\` → `tests/`
- **Seeders**: Run `php artisan seed` to populate admin user (or use factories in tests)
- **Queue**: Currently **synchronous** (blocking, ideal for development) — change in `.env` for async
- **Mail**: Uses Laravel Mail facade with configurable driver (Mailtrap for dev)
- **No Vue SPA**: Vue components are optional; frontend is primarily Blade templates
- **Simple domain**: No complex business logic, events, or state management (yet)
- **Middleware**: Standard Laravel auth middleware on protected routes
